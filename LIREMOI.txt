AfriControl — poste
Inspection du 1er octobre 2026

Corrigé dans cette livraison
- La couche nuit et tout agrandissement ne sont plus dessinés en gros carreaux. La tuile native reste nette. Si on agrandit, l'image est lissée.
- La vue proche (Ident) demande la mosaïque à 0,3 m là où la tuile existe. Sinon le niveau réel en dessous, pas une grille de couleurs.
- Le 1090ES interroge adsb.fi puis adsb.lol, une cellule après l'autre, pour ne plus perdre le flux sur un refus 429.
- Une piste 1090ES verrouillée est croisée avec le METAR le plus proche, le SIGMET qui la couvre, et le GNSS (NIC du bord, cellule au sol).

Constat, pas un défaut du poste
- À l'heure des captures, FTTJ, Niamey et Accra n'avaient aucun squitter. Le même flux en avait 31 au-dessus de Paris. Le METAR FTTJ affiché était bien le message réel.
- La photo de route avec un véhicule est la mosaïque publique fine. Ce n'est pas une prise de la dernière heure. La photo de l'heure reste Meteosat, environ 1 km, sur les vues larges.

Installation
- Node 22. Dans ce dossier : npm install, puis npm run dev.
- Le poste écoute sur le port 8080.
- Poste isolé / hors ligne : l'authentification est COUPÉE par défaut (fichier .grok/app-env.json,
  VITE_AUTH_ENABLED=false) — le poste ouvre DIRECTEMENT la console, sans login ni base de données.
  C'est le bon mode pour un site isolé où l'accès physique au poste est déjà contrôlé.
  Si le poste reste bloqué sur « Chargement du poste… », c'est que l'auth s'est activée sans
  serveur d'auth derrière : vérifier que .grok/app-env.json existe, ou lancer
  VITE_AUTH_ENABLED=false npm run dev (Windows : $env:VITE_AUTH_ENABLED="false"; npm run dev).
- Pour ACTIVER un login multi-agents : mettre VITE_AUTH_ENABLED=true ET fournir une base
  (DATABASE_URL) ; sinon l'auth n'a pas de serveur et le poste reste sur l'écran de chargement.

Lancer comme un vrai serveur (sans mode dev)
- npm run dev est pratique mais c'est le mode développement. Pour un serveur autonome lançable
  avec node, builder avec le preset node-server :
    NITRO_PRESET=node-server npm run build
  → produit .output/server/index.mjs. Le lancer :
    PORT=8080 node .output/server/index.mjs
  Flux externes (1090ES, météo) derrière un proxy : ajouter NODE_USE_ENV_PROXY=1 et HTTPS_PROXY.
- Par défaut le build vise Vercel ; NITRO_PRESET choisit la cible, rien d'autre à changer.
- Persistance (journal, personnel, preuves) : fournir une base Postgres via DATABASE_URL. Sans
  base, le cœur live (1090ES, carte, météo, phonie) fonctionne, mais rien n'est conservé au redémarrage.

Intégrer ta propre API
- Un point d'entrée HTTP interne : créer src/routes/api/<nom>.ts sur le modèle de src/routes/api/tile.ts
  — createFileRoute("/api/<nom>") avec server.handlers.GET/POST. Accessible sur /api/<nom>.
- Appeler TON API externe depuis le serveur (la clé reste côté serveur, jamais exposée au navigateur) :
  créer un module <nom>.server.ts qui fait le fetch, et l'exposer via createServerFn (voir
  src/lib/vigilair/live-feeds.ts). Le composant appelle la fonction, le navigateur ne voit que le résultat.

Assistant IA DeepSeek (ta clé) — Capteurs > Outils
- Le poste intègre un assistant qui raisonne sur l'image live réelle (1090ES, METAR, SIGMET, Kp).
  Il répond en français, bref, sans inventer de pistes. Réception seule : il ne commande rien.
- Ta clé DeepSeek est un SECRET : elle vit UNIQUEMENT dans la variable d'environnement du serveur
  AFRICONTROL_DEEPSEEK, posée AU LANCEMENT. Jamais dans le code, le zip livré, Git, ni .grok/app-env.json
  (ce n'est PAS une variable VITE_ : celles-là partent dans le navigateur). La clé ne quitte jamais le
  serveur ; le navigateur ne reçoit que la réponse texte.
    AFRICONTROL_DEEPSEEK=sk-xxxx PORT=8080 node .output/server/index.mjs     (serveur autonome)
    AFRICONTROL_DEEPSEEK=sk-xxxx npm run dev                                 (dev)
    Windows PowerShell :  $env:AFRICONTROL_DEEPSEEK="sk-xxxx"; npm run dev
- Capteurs > Outils > « Assistant IA du poste » : bouton « Tester la clé » (vérifie que l'API répond)
  et un champ question libre. Le même bouton sert au « Briefing situation » (DeepSeek si la clé est posée).
- IMPORTANT : si une clé a été exposée (collée dans un message, un ticket, une capture), la RÉVOQUER et en
  régénérer une sur platform.deepseek.com. Une clé ne se partage pas en clair ; seul le serveur la détient.

Antenne 1090 du poste (clé SDR + dump1090)
Lancer dump1090 avec le port brut AVR, et un port web qui ne prend pas 8080 (celui de AfriControl) :
  dump1090 --interactive --net --net-ro-port 30002 --net-http-port 8090 --aggressive
AfriControl s'y branche seul sur 127.0.0.1:30002 et décode chaque trame (Capteurs > Antenne).
Récepteur sur une autre machine :  AFRICONTROL_1090=192.168.1.50:30002 npm run dev
  (Windows PowerShell :  $env:AFRICONTROL_1090="192.168.1.50:30002"; npm run dev)
Position de l'antenne :  AFRICONTROL_ANTENNE=12.1331,15.0339   Couper la liaison :  AFRICONTROL_1090=off
Réception seule : AfriControl décode l'ADS-B / Mode S entendu en clair, il n'interroge ni n'émet.
Les anciens noms VIGILAIR_1090 / VIGILAIR_ANTENNE sont encore lus : un poste déjà réglé n'a rien à changer.

GPS du poste (position + heure réelles) — Capteurs > GNSS
- Branche un RÉCEPTEUR GPS (clé USB GPS, module u-blox, ou un terminal qui sort du NMEA). L'antenne
  GPS seule ne suffit pas : une antenne sort du signal RF, pas des données — il faut le récepteur.
- Le poste lit le NMEA et en tire la position et l'heure UTC réelles ; un fix sert aussi de position
  d'antenne au décodage 1090 (prioritaire sur AFRICONTROL_ANTENNE). Lecture seule, rien n'est émis.
    AFRICONTROL_GPS=/dev/ttyUSB0 npm run dev        clé USB / série (Linux/macOS ; baud AFRICONTROL_GPS_BAUD, défaut 9600)
    AFRICONTROL_GPS=127.0.0.1:2947 npm run dev      flux NMEA en TCP (gpsd « gpspipe -r », ser2net, device réseau)
    AFRICONTROL_GPS=off                             coupe la liaison (défaut : non réglée)
- Windows : expose la clé USB GPS en TCP (gpsd, ser2net, com2tcp) puis AFRICONTROL_GPS=hote:port.
- Capteurs > GNSS montre le fix (position, UTC, satellites, HDOP) ; le diagnostic (Outils) l'affiche aussi.

Imagerie satellite de nuit — honnêtement
- « Visible » est de la lumière solaire réfléchie : de nuit, c'est NOIR (physique, pas un bug).
- Pour les nuages la nuit : « IR 10.5 » (infrarouge, 24 h/24) ou « Nuit » (bande jour/nuit VIIRS :
  nuages au clair de lune + lumières des villes). La capture nocturne avec villes = cette couche-là.
- « Visible » n'est noir la nuit QUE sur les vues LARGES (AES/Sahel/Monde), où il vient du
  géostationnaire. En DÉTAIL (1,2 m / 0,3 m / Veille / Approche), « Visible » est l'ARCHIVE Esri
  World Imagery : une mosaïque NETTE, valable jour comme nuit. On lit les rues la nuit aussi.
- Bascule AUTO jour/nuit (bouton sous les couches, actif par défaut) : la nuit, SEULES les vues
  larges passent en « Nuit » (le détail garde l'archive nette) ; retour « Visible » au jour ou dès
  qu'on repasse en détail. Un choix manuel (IR, Nuit…) n'est jamais écrasé ; « Auto nuit coupé »
  laisse la main. Le bouton affiche « Auto · Nuit » seulement quand il a réellement basculé.
- Imagerie qui semble floue/sombre alors qu'on est EN LIGNE : laisser 10–20 s au premier affichage
  d'une zone (l'imagerie fine Esri 0,3 m charge progressivement, tuile par tuile). Tant qu'elle
  n'est pas arrivée, le poste montre la mosaïque locale plus grossière (37 m) si elle est installée,
  sinon du sombre. En ligne, l'imagerie fine finit toujours par remplacer la locale.

Couverture imagerie par continent — quelle couche pour voir le monde
- Pour une vue qui couvre Afrique + Moyen-Orient + Europe + Russie + Asie en continu : utiliser la
  couche « IR 10.5 » (infrarouge). Mesuré : l'IR rend une imagerie riche partout, 24 h/24 (y compris
  Asie et Russie Est). La couche « Nuit » (VIIRS) couvre aussi le monde la nuit (lumières des villes).
- AUTO : le bouton « Auto IR monde » (sous les couches, actif par défaut) bascule tout seul sur IR
  dès qu'on passe aux vues larges (AES / Sahel / Monde) → couverture monde garantie, jour et nuit ;
  retour « Visible » en détail (archive nette). Priorité : IR (vue large) > Visible (détail). Un choix
  manuel de couche n'est jamais écrasé. « Auto IR coupé » laisse « Auto jour/nuit » gérer la nuit.

Actualisation de l'imagerie — à quelle cadence (honnêtement)
- Vue continent / monde (IR ou Visible géostationnaire, Meteosat/GOES/Himawari) : ~10 minutes (le
  satellite rebalaie le disque toutes les ~10 min). C'est le quasi temps réel pour nuages / météo.
- Couche « Nuit » (VIIRS DNB, satellite polaire) : ~1 à 2 passages par jour → quotidien, pas continu.
- Détail « Visible » (Esri World Imagery 0,3 m) : c'est une ARCHIVE, pas du live — des mois à des
  années selon la zone. Le crédit en bas de carte le dit (« archive, pas une prise du jour »).
- Sentinel-2 (couche S2) : revisite ~5 jours, composite « moins nuageux » ≤ 20 jours.
- Feux FIRMS (VIIRS thermique) : quelques heures à quotidien. METAR/SIGMET : à chaque relevé (~20 s
  côté poste, sur des bulletins publiés toutes les ~30–60 min). 1090ES réseau : ~toutes les 20 s.
- « Visible » est plus limité : c'est le disque géostationnaire METEOSAT (Afrique, Moyen-Orient,
  Europe, Russie Ouest) ET seulement de JOUR (lumière solaire réfléchie). L'Asie / l'Extrême-Orient
  ne sont pas sur Meteosat, et la moitié du globe en nuit est toujours noire sur Visible — c'est la
  physique du géostationnaire, pas un bug. « Rien de vue » en vue large = on est sur Visible, de nuit
  ou sur l'Asie. Passer sur « IR 10.5 » pour la couverture monde continue.

Imagerie en haut zoom sur un SITE ISOLÉ — la vérité
- L'imagerie gratuite (Esri World Imagery) n'a PAS le 0,3 m partout. Sur une grande ville (ex. FTTJ)
  elle va jusqu'au 0,3 m ; sur un site isolé du Sahel, le plus fin existant est souvent ~2–5 m (zoom
  16–17). Au-delà, la tuile n'existe pas (404). Ce n'est pas un bug du poste, c'est la couverture.
- Le poste affiche désormais la MEILLEURE imagerie réellement disponible (le zoom le plus fin qui
  existe, agrandi) au lieu d'un carré vide, et le GSD affiché dit la VRAIE résolution (ex. « GSD 2.4 m »
  à la place d'un faux « 0,3 m »). Honnête : on ne maquille pas du 2 m en 0,3 m.
- « Détection » (bandeau voiture/pirogue/homme) N'EST PAS une détection d'objets : c'est un indicateur
  de RÉSOLUTION. À partir du GSD réel, il dit ce que l'image PEUT séparer (voiture, pirogue…) et ce
  qu'elle ne peut pas (« pas une plaque, pas un nom »). Sur un site à 2–5 m, il dira honnêtement qu'on
  ne distingue ni un homme ni un véhicule fin. Pour du vrai sous-métrique sur ton site, il faut une clé
  commerciale taskée (Maxar/Planet) — le poste ne fabrique jamais un faux « live » ni une fausse détection.
- Chaque couche crédite sa vraie source et son vrai âge ; rien n'est simulé.

Verrou auto sur piste réelle
- Sans choix de l'opérateur, le panneau de droite suit la piste 1090ES réelle prioritaire :
  urgence (7500/7600/7700) > drone B6 > militaire > GNSS douteux (NIC < 5) > plus proche de FTTJ.
  Urgence et B6 comptent sur le Tchad, le Darfour et l'AES ; militaire et GNSS sur Tchad et Darfour.
- Le bandeau « VERROU AUTO » dit pourquoi. Un clic sur une piste reprend la main ; « Rendre au
  verrou auto » la lui redonne ; « Couper le verrou auto » laisse le panneau vide.
- Un inject ou un rejeu n'est jamais pris par le verrou auto. La carte ne bouge pas toute seule.

Inject « Rejeu réel »
- Injecter > Rejeu réel : rejoue de VRAIS avions reçus, pas un scénario. Bande de ce poste (les
  30 dernières minutes de veille) ou, au démarrage, l'archive réelle livrée (12 min enregistrées
  le 4 octobre 2026 sur 15 cellules africaines). Entre deux relevés, la position est interpolée.
- Chaque piste porte « REJ » et son heure d'origine ; le bandeau dit d'où vient la bande. ×1 ou ×4.
- Un rejeu ne compte jamais comme live, ne déclenche pas d'intrusion de zone et n'est pas
  croisé avec la météo du jour. Nouvelle archive : node scripts/rejeu-enregistrer.mjs 12 30

Symbologie APP-6 et radar
- Les pistes portent le cadre OTAN APP-6 (le cadre = l'affiliation ; ouvert en bas = aérien).
  Inconnu est l'état par défaut : sans IFF ami ni mandat levé, une piste reste inconnue.
- PPI : portées jusqu'à 20 000 km, vecteur vitesse, nord vrai/magnétique, bascule symboles APP-6 /
  formes plateforme. Fiche « interception » : toutes les données reçues. À 8000 km « couverture
  Afrique », à 12 000+ « couverture monde · tous continents ».
- Débruitage (touche D, ou « Pertinent » dans Peinture) : à large portée le scope se remplit de
  transit civil lointain. Le débruitage ne garde que ce qui compte pour la sûreté du site — urgence,
  militaire, GNSS dégradé (NIC < 5), et tout contact à moins de 300 km de FTTJ — plus la piste
  verrouillée. Exemple mesuré : 128 contacts à 20 000 km → 3 pertinents. La liste et le compteur
  se rafraîchissent aussitôt. Le reste n'est pas supprimé, juste masqué tant que le débruitage est actif.
- Le « clutter » cosmétique du scope (neige radar) est bas par défaut (6 %), réglable dans Peinture.
- Fond de carte : là où l'imagerie géostationnaire n'existe pas (zoom monde/continent, pôles), le
  poste sert une tuile vide propre au lieu d'erreurs 404 qui polluaient la console — rien à régler.

Balayage continental (chef de division) — Capteurs > 1090ES
- Par défaut le poste interroge 3 cellules du continent par relevé (courtoisie envers les API
  publiques). Le chef active le balayage total : toutes les cellules Afrique + ancres mondiales
  (Europe, Amériques, Asie, Océanie) à chaque relevé — le radar « tous continents » montre alors
  de VRAIS contacts 1090ES, pas une carte vide. Les cellules partent en lots parallèles bornés.
- Toute piste réelle est verrouillable : un clic sur l'indicatif dans la liste 1090ES l'ouvre.

Diagnostic du poste — Capteurs > Outils
- Une vue qui dit honnêtement l'état de CHAQUE source : 1090ES réseau, METAR, SIGMET, météo spatiale,
  antenne 1090 locale, phonie ATC, clé assistant DeepSeek, clé imagerie Sentinel. Vert = répond,
  jaune = réglé mais rien reçu / vieux, rouge = réglé mais en échec, gris = non réglé (optionnel).
- Il n'interroge PAS les API (aucun martèlement) : il lit le dernier relevé en cache, l'état mémoire
  de l'antenne et de la phonie, et la présence des clés. « 0 contact » est un vrai constat là où le
  réseau public n'a pas de récepteur, jamais une panne déguisée. Bouton « Rafraîchir ».
- Chaque ligne en défaut porte un bouton d'action direct : « Régler l'antenne » (onglet Antenne),
  « Ouvrir Phonie ATC », « Configurer la clé » (DeepSeek / Sentinel). On va au bon réglage en un clic.

Compte rendu de quart (DeepSeek) — Journal de preuve
- En tête du Journal : bouton « Rédiger le compte rendu ». DeepSeek rédige un AAR structuré (période,
  volume, faits marquants, points d'attention, recommandation pour la relève) à partir des SEULS
  bulletins versés. Les injects sont marqués EXERCICE et ne sont jamais comptés comme trafic réel.
- La clé reste au serveur (AFRICONTROL_DEEPSEEK). Le compte rendu est une aide à relire et valider,
  pas une pièce scellée : les bulletins hashés restent la preuve.

Enregistrements archivés — Capteurs > Outils
- Copie de ce que le poste a réellement entendu (veille 30 min), écrite sur disque dans recordings/.
  Archivage auto toutes les 15 min dès 3 min de veille (activable/désactivable par le chef), plus
  « Archiver maintenant ». Téléchargeable en JSON (format du rejeu réel).

Phonie ATC — réception seule (Capteurs > Phonie ATC)
- Enregistre le flux audio de TON propre récepteur (clé SDR + rtl_airband/rtl_fm, bande aéro VHF
  publique) : AFRICONTROL_ATC=http://127.0.0.1:8000/atc.mp3 npm run dev
- Réception seule : le poste lit un flux public et l'archive, sans limite (segments de 10 min),
  activable/désactivable. Il n'accorde aucune radio, ne décode pas la parole, n'émet jamais.
  Segments téléchargeables. Pas d'écoute d'autre chose que l'aéronautique en clair.

Alertes feu (FIRMS) — ce que le capteur peut, honnêtement
- Détection thermique VIIRS : foyers groupés, puissance FRP (MW), confiance, jour/nuit, ville la
  plus proche. Seuil abaissé au théâtre élargi (Tchad, Darfour, AES).
- Limite physique : le pixel VIIRS fait 375 m. On repère un FOYER, pas l'image d'une voiture.
  Voir une voiture qui brûle demande du sous-métrique (30 cm) commercial et taské (Maxar, Planet) —
  pas un flux public rafraîchi toutes les 30 min. Sans clé d'un fournisseur commercial, le poste
  n'affiche pas un faux « live » : le crédit en carte dit toujours la vraie source et le vrai âge.

Phénomènes mondiaux — le lointain à un clic, sans noyer le poste
- Les crues, cyclones, séismes, volcans et feux du MONDE ENTIER sont captés en temps réel (GDACS,
  EONET, USGS, FIRMS) et restent sur la carte et dans les graphiques SANS sonner. Un phénomène
  lointain (Indonésie, Népal…) ne doit pas noyer la veille de FTTJ : il n'arme pas d'alerte.
- Pour les retrouver quand même, le bandeau d'alertes porte une pastille « N monde » (icône globe).
  Un clic ouvre le volet « Phénomènes mondiaux » : TOUS les événements réels, triés par gravité puis
  distance, chacun avec « Capture imagerie » (imagerie réelle de la zone — Sentinel-2 10 m si clé,
  sinon IR/Esri). Réception seule : le poste regarde, il ne commande rien.
- SITES MINIERS : une crue, un feu ou un séisme à ≤ 200 km d'un site minier (Komé, Essakane, Tasiast,
  Geita, Kibali…) SONNE toujours en alerte, où qu'il soit sur le continent, même hors du théâtre de
  FTTJ — l'alerte porte « près de <site> (<km>) ». La sûreté d'un site isolé prime ; seuls les feux
  FIRMS lointains de masse restent filtrés pour ne pas saturer.

Imagerie Sentinel-2 fraîche (Copernicus) — Capteurs > Outils, couche « Sentinel-2 »
- Le poste ne possède pas de satellite. Il interroge l'API Copernicus avec le compte GRATUIT de
  l'opérateur (Copernicus Data Space Ecosystem) : images Sentinel-2 fraîches, 10 m natif. On lit une
  piste, un bâtiment, un convoi — pas une voiture isolée. Composite « moins nuageux » ≤ 20 jours,
  crédité honnêtement (fenêtre réelle, jamais un faux « live »).
- Clé gratuite : compte sur dataspace.copernicus.eu, client OAuth, puis
  AFRICONTROL_SENTINEL_ID=<id> AFRICONTROL_SENTINEL_SECRET=<secret> npm run dev
- « Tester la clé » dans Outils vérifie que le jeton est obtenu. Lecture seule : le poste lit des
  images publiques, il ne commande aucun satellite. Pour le sous-métrique (30 cm), il faut une clé
  commerciale (Planet/Maxar) — je ne simule pas ce que le compte gratuit ne donne pas.

Comparateur avant/après — Capteurs > onglet « Changement »
- Pas de direct : un satellite ne repasse que tous les quelques jours. On ne traque pas une voiture
  qui roule ; on compare deux PASSAGES DATÉS du même périmètre. C'est pour ça qu'on lance des
  satellites : chaque passage est une date, et le changement se lit ENTRE deux dates.
- Choisir un site minier, « Analyser le périmètre » : le poste va chercher deux composites
  Sentinel-2 10 m du même cadre — un récent (20 derniers jours) et un ancien (fenêtre finissant il y
  a ~45 j). Un curseur (swipe) montre l'avant et l'après ; le bouton « Afficher le changement »
  allume en orange ce qui a bougé (une piste neuve, un bâtiment, un engin apparu) et donne un % de
  changement estimé.
- Honnêteté : c'est une DIFFÉRENCE D'IMAGE, pas une détection d'objet ni une identification. À 10 m
  on lit une piste ou un carreau, jamais une voiture isolée ni un visage (comme Google montre la
  scène mais floute les plaques). Réception / lecture seule : le poste lit Copernicus, il ne commande
  aucun satellite. Nécessite la clé Copernicus gratuite (même clé que la couche « Sentinel-2 ») ;
  sans clé, l'onglet le dit au lieu d'inventer une image.

Sites surveillés — ajouter ses propres sites au périmètre de sécurité (Capteurs > Changement)
- Le lot d'usine (sites miniers) n'est jamais complet. L'opérateur ajoute ses propres sites — camp,
  poste avancé, forage, village, pont — avec un champ : Nom, Latitude, Longitude, Rayon (km).
- Chaque site ajouté compte comme un site intégré :
  · une CRUE / un SÉISME / un VOLCAN à moins de 200 km SONNE (impact régional) ;
  · un FEU à moins de 40 km SONNE (serré, pour ne pas sonner sur chaque feu de brousse du Sahel à
    150 km mais alerter dès qu'un foyer touche le périmètre) ;
  · le périmètre est armé et évalué contre l'intrusion drone, comme une bulle de protection ;
  · le site devient sélectionnable dans le comparateur avant/après.
  L'alerte porte « près de <site> (<km>) », et le badge « site surveillé » apparaît dans le volet
  Phénomènes mondiaux.
- RECHERCHE DE LIEU intégrée : en Afrique les cartes publiques décrochent après Abéché (Ennedi, BET,
  Ouaddaï, Wadi Fira… Amdjarass n'est sur presque aucune carte). Un champ « Rechercher un lieu »
  contient un répertoire Tchad/Sahel (Amdjarass, Fada, Faya, Abéché, Biltine, Iriba, Guéréda, Am
  Timan, Mao, Bongor, Doba, Ounianga, Zouar, Gouro… + sous-préfectures) : tape le nom, le poste
  remplit les coordonnées — sans dépendre d'une carte externe mauvaise ou hors-ligne. Tolère les
  accents et la casse (« amdjarass » = « Amdjarass »). Ces lieux affinent aussi le « lieu le plus
  proche » des phénomènes dans tout le théâtre tchadien.
- STOCKAGE PARTAGÉ : les sites sont enregistrés SUR LE POSTE (serveur, fichier data/watch-sites.json),
  donc partagés par tous les navigateurs qui parlent à ce poste et conservés au redémarrage — plus
  seulement dans un seul navigateur. Un miroir local sert à peindre instantanément au chargement.
  Jusqu'à 1000 sites. Réception seule : on surveille, on n'émet rien. (Pour partager entre PLUSIEURS
  postes physiques distincts, il faudrait un serveur central commun — à câbler si besoin.)

Navigation directe jusqu'au site (Capteurs > Navigation)
- En zone saharo-sahélienne (BET, Ennedi) il n'y a pas de route : on tient un CAP, pas un itinéraire
  routier (comme en mer, comme au désert). Le poste calcule, d'un point à un site :
  · le CAP VRAI (° + rose des vents) et une flèche boussole ;
  · la DISTANCE grand-cercle (orthodromie) et l'ETA à la vitesse de marche choisie.
- Départ : bouton « Position GPS » (si une antenne GPS est branchée), un lieu du répertoire, un site
  surveillé, ou des coordonnées. Destination : idem. Cap vrai — ajouter la déclinaison magnétique si
  on suit une boussole.
- SÛRETÉ DE L'AXE : le poste balaie la ligne droite et signale les obstacles CAPTÉS (crue, feu,
  séisme) à moins de 25 km de l'axe, avec « à X km sur l'axe · Y km à gauche/droite ». « Axe dégagé »
  s'il n'y en a pas au dernier relevé.
- Honnêteté : navigation directe, PAS d'itinéraire routier et PAS de guidage d'arme. Le relief, les
  oueds et les pistes se lisent sur l'imagerie et à l'œil ; ceci aide un véhicule à tenir un cap.
  Réception seule.

Durcissement défensif
- En-têtes de sécurité sur chaque réponse (nosniff, Referrer-Policy no-referrer, Permissions-Policy
  capteurs coupés). Aucune télémétrie tierce. Les sources externes (1090ES, météo…) sont
  interrogées PAR LE SERVEUR : l'adresse IP de l'opérateur n'est jamais exposée aux agrégateurs.
- Audit des dépendances : 0 vulnérabilité (npm audit, dépendances de production).

Couverture 1090ES réelle (mesurée en ligne, octobre 2026)
Les agrégateurs publics (adsb.lol, adsb.fi) n'ont presque aucun récepteur au Sahel et en Afrique
centrale/de l'Ouest : 0 avion à N'Djamena, Niamey, Khartoum, Kano, Abuja, Bamako, Dakar ; 2 à Douala.
Ils en ont au Maghreb, en Égypte, en Afrique de l'Est et australe : le poste les interroge en
rotation (couverture continentale). Pour de vrais avions au-dessus de N'Djamena, il faut l'antenne
du poste (dump1090, voir plus haut). Le trafic hors zone ASECNA est marqué « CIVIL » (neutre APP-6).

Liaison Internet du site (wifi opérateur / Starlink / Thuraya) — Capteurs > Outils
- Ces liens sont gérés par le SYSTÈME (Windows/Linux) : on connecte le PC au wifi, à Starlink ou au
  terminal Thuraya comme d'habitude ; AfriControl utilise le lien Internet actif, il n'en pilote aucun.
- « Liaison Internet » (en tête des Outils, bouton « Tester la liaison ») teste en direct si le poste
  atteint ses sources (imagerie, réseau 1090ES, météo) et dit EN LIGNE / PARTIEL / HORS LIGNE.
    EN LIGNE  : tout répond, l'imagerie live charge normalement.
    PARTIEL   : un domaine est bloqué par un pare-feu → autoriser les domaines listés plus bas.
    HORS LIGNE: pas d'Internet (lien coupé) → l'imagerie live ne charge pas ; le poste retombe sur la
                mosaïque locale SI les packs de tuiles sont installés (sinon carte sombre).
- Carte sombre ? 1) « Tester la liaison » : hors ligne → vérifier wifi/Starlink/Thuraya ; 2) en ligne
  mais sombre → laisser 10–20 s à l'imagerie fine pour charger (tuile par tuile) ; 3) pour l'offline,
  installer les packs de tuiles.
- Packs de tuiles hors-ligne (mosaïque locale quand il n'y a pas de ligne) : EXTRAIRE les archives
  AfriControl-2-tuiles-z8.zip et AfriControl-3-tuiles-z10-z12.zip À LA RACINE du dossier — elles
  créent public/sentinel/<z>/<x>/<y>.jpg (c'est là que le poste les lit). Fournies à part du zip de
  code pour ne pas l'alourdir. En ligne (wifi/Starlink/Thuraya), elles ne sont PAS nécessaires :
  l'imagerie fine vient du réseau ; elles ne servent que si le lien tombe.

Derrière un proxy d'entreprise
Le serveur du poste (Node) n'utilise un proxy que si on le lui dit :
  NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://proxy:port npm run dev   (Node 22.21 ou plus récent)
